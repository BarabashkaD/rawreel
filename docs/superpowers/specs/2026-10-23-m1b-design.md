# M1b design: platform and presentation

Status: binding design for the M1b plan. Date 2026-10-23. Inputs: the spec (approved, §17 final), the
M1a code on branch `m1a` (dvv-base c8f88a3, dvv-registry 8fff8cb, dvv-gpu 7d6cad6, rawreel-workspace
63ab483), the M1a ledger (`rawreel-workspace/.git/sdd/`), and the M1a plan conventions.

Web-checked facts: wxWidgets **3.3.4** was released on 2026-10-10. GitHub lists the SHA256 of
`wxWidgets-3.3.4.tar.bz2` as `815c16cafa4fcbfcf25c5c0a3418309c62257b8a3b6f91d85a1367a134f98c98`;
Task 4 confirms it by downloading. wx 3.3.4 CMake options are `wxBUILD_*` and `wxUSE_<lib>`
(`builtin`/`sys`/`OFF`); consumers use `find_package(wxWidgets CONFIG REQUIRED COMPONENTS core
base)`. The docs do not say whether a Debug and a Release build can share one prefix (R1). Lavapipe
exposes `VK_KHR_xlib_surface` and FIFO on X11; surface queries need an X server, hence Xvfb in CI.

## 1. Scope and exit criterion

**Exit criterion (spec §15):** `rawreel-gui` opens a wx window with a Vulkan viewport that shows a
shader test pattern. Resizing redraws the pattern at the new size. Minimising and restoring work. On
Windows this is checked on local hardware. On Linux it is checked in WSL (lavapipe on WSLg) and, by
an automated `--selftest`, under Xvfb.

**In scope**
- **dvv-platform (new):** native window descriptions, Win32/Xlib surface creation, `DynamicLibrary`
  with a system-directory-only mode, and a test-only native `TestWindow`.
- **dvv-gpu:** the loader comes through `DynamicLibrary` (System32 on Windows); opt-in surface and
  swapchain extensions; `Presenter` with its own thread, swapchain, acquire/present, the
  resize/minimise handshake, and out-of-date recovery (a lost surface fails the presenter).
- **rawreel (new, local):** `rawreel-gui` skeleton (wx app, frame, one native child viewport), a
  test-pattern compute shader, and `--selftest`.
- **rawreel-workspace:** wxWidgets 3.3.4 in the superbuild (Debug+Release on MSVC), `libpng-2.0` in
  the gate, the validation layer with Linux WSI, wiring for the new repos, presets, and CI changes
  (written and checked locally; live at publishing).
- **M1a leftovers:** `createComponent<I>`, the UTF-8 environment API, and `vulkan-1.dll` from
  System32.

**Out of scope** (see §12): `IAsyncFileReader` (M2), Wayland, macOS, HDR, more than one frame in
flight, mailbox mode, the Session, menus and panels, device-lost recovery (M3), and publishing to
GitHub.

## 2. Decisions

**D1. The wx frame lives in a new local `rawreel` repo (`rawreel-gui`).** Alternatives: a demo in
dvv-platform breaks "nothing below rawreel-gui depends on wx" (§3.2); a workspace `tools/` app would
make the tooling repo a product and be thrown away. `rawreel` is where the GUI must live (§3.1); its
viewport, startup path, leak-check shutdown and `--selftest` carry straight into M3.

**D2. Surface creation is two free functions over a `NativeWindow` variant, not an
`ISurfaceFactory` interface.** A closed `std::variant` (Win32, Xlib; later Wayland, Metal) with
`surfaceInstanceExtensions()`/`createSurface()` gives the same run-time choice with no object,
lifetime or registration. dvv-platform includes only the Vulkan C headers and returns
`std::expected<VkSurfaceKHR, VkResult>`, so the one `VkResult`→`Errc` mapping stays in dvv-gpu
(§11). Spec §3.1/§10.4 text is updated (Task 13b).

**D3. `DynamicLibrary` is a move-only RAII handle (exempt from §9.4, like a lease).**
`LibrarySearch::SystemDirectory` (`LOAD_LIBRARY_SEARCH_SYSTEM32`) closes the DLL-planting gap for
`vulkan-1.dll`. Process-wide `SetDefaultDllDirectories` was rejected: it would change the search for
wx and every later run-time library. `vk::detail::DynamicLoader` is dropped; the loader is still
never unloaded (`keepLoaded()`).

**D4. Fence acquire, host wait, semaphore-less present; rendering through the submit thread.** Per
frame the presenter thread (1) acquires with a fence and waits for it on the CPU (it may block, §4);
(2) hands one submission to the submit thread: the client's commands, a blit into the swapchain
image and a transition to `PRESENT_SRC`; (3) once it completes, calls `vkQueuePresentKHR` with no
wait semaphores under the queue mutex. This keeps the submitter rule "no batch waits on a
semaphore", needs no binary-semaphore reuse (the known present-semaphore problem without
`VK_KHR_swapchain_maintenance1`), and keeps "the presenter never records or submits". Rejected: an
acquire semaphore waited by the submission (submitter contract change, per-image semaphores);
presenting from the submit thread (breaks §4). Cost: one frame in flight plus a CPU round trip,
fine at 60 fps; measured in M3 (F1).

**D5. Exactly one frame in flight.** The provider is called again only after the previous
submission completed, so the client reuses one image and buffer, and recreation always happens
between frames.

**D6. The client renders into its own `GpuImage`; the presenter blits it to the swapchain (scaled
if sizes differ).** Exposing swapchain images would need a new public image type in
`CommandRecorder`, which tracks only `GpuImage` layouts. The blit keeps the API to one
`shared_ptr<GpuImage>`, matches the later composite→encode display path (§8), and works with M1a
buffer-only shaders (shader → buffer → `copyBufferToImage`). It is an internal recorder operation
reached through `detail::Access`.

**D7. Lazy recreation on the presenter thread, between frames; the old swapchain is destroyed after
`vkQueueWaitIdle`.** The new swapchain gets `oldSwapchain`. Without maintenance1 present fences,
queue-idle (under the queue mutex) is the accepted practice for knowing that presentation is done
with the old images, not guaranteed by the Vulkan spec; exact retirement comes in F3. It happens
only on resize or out-of-date. This replaces §4's "old images retire through the
context" (spec update).

**D8. Surface capabilities decide the size.** `currentExtent` is authoritative on Win32 and X11; the
GUI's `resize()` is only a change hint (used when `currentExtent` is `0xFFFFFFFF`), which avoids DPI
and logical-pixel mistakes. A 0×0 `currentExtent` (Windows while minimised) means hidden.

**D9. Visibility is explicit.** The GUI calls `setVisible` on iconize/restore and hide/show and
`requestFrame()` on paint. While hidden or 0-sized the presenter does nothing and runs no timers; a
pending request is served on restore.

**D10. The decision logic is a pure class (`detail::PresenterLogic`)**, unit-tested without a GPU on
every CI job, Windows included; the thread only executes Vulkan calls and reports outcomes. This is
the main answer to "presentation without a display".

**D11. Presentation tests use raw native windows, not wx.** `TestWindow` (`CreateWindowExW` /
`XCreateSimpleWindow`) lets the dvv-gpu presentation tests run under every sanitizer without GTK
noise. Only rawreel's GUI smoke test uses wx, and only in non-sanitizer jobs. Linux display tests run
under `xvfb-run`.

**D12. One skip switch.** Display tests exit 77 without a usable device or a display;
`DVV_REQUIRE_GPU=1` turns both into failures (Linux CI under Xvfb). No new variable.

**D13. wxWidgets 3.3.4, static.** MSVC builds Debug (`/MDd`) and Release (`/MD`): a Release-only
static wx cannot link into Debug builds (LNK2038, as vk-bootstrap in M1a), and wx is too large to
compile into our targets. The superbuild gains `CONFIGS <config>...` (default Release). Linux:
Release only (no libstdc++ debug ABI split), GTK3, zlib/libpng from the system (`sys`); Windows:
`builtin`. Off everywhere (not needed through M4): regex, expat/XML/XRC, richtext, STC, webview,
mediactrl, OpenGL, webrequest, secret store, JPEG, TIFF, WebP, lunasvg. That keeps the licence
small (no PCRE2 exception, no IJG). Two declarations with `ONLY_ON`, as for Slang.

**D14. Licence.** wx is `LGPL-2.0-or-later WITH WxWindows-exception-3.1` (the SPDX form of the
wxWindows Library Licence; the deprecated id `wxWindows` is not used); the gate already allows the
pair. Expressions: Windows `LGPL-2.0-or-later WITH WxWindows-exception-3.1 AND Zlib AND libpng-2.0`
(bundled zlib, libpng 1.6, nanosvg); Linux `LGPL-2.0-or-later WITH WxWindows-exception-3.1 AND Zlib`
(nanosvg). **Gate change:** add `libpng-2.0` (permissive, zlib-style, not OSI-approved) to
`DVV_SPDX_PERMISSIVE`, with a test. This allowlist change is a **user decision before Task 3**,
recorded in spec §17. Recommendation: accept, because the M3 PNG exporter (spec §15) needs libpng
anyway. Status: accepted for static linking (decisions log D4; the user may revisit it before
Task 3). Fallback if declined: `-DwxUSE_LIBPNG=OFF` on Windows, Windows expression
`LGPL-2.0-or-later WITH WxWindows-exception-3.1 AND Zlib`, no gate change, and the M3 PNG route is
reopened then. If Task 4 finds more bundled code, its ids are added; an id outside the allowlist
stops the task for a user decision.

**D15. Window-system support is opt-in.** `GpuRegistryOptions::windowSystem` adds `VK_KHR_surface`
plus the platform extension (headless by default: `dvv-gpu-info` and the CLI are unchanged);
`ContextOptions::presentation` adds `VK_KHR_swapchain`; `OptionalFeatures::swapchain` reports it.

**D16. Swapchain:** `B8G8R8A8_UNORM` or `R8G8B8A8_UNORM` with `SRGB_NONLINEAR`, else the first
format; `TRANSFER_DST` usage and `BLIT_DST` required; FIFO only; `max(minImageCount + 1, 2)` images,
capped. The pattern is sRGB-encoded RGBA8 code values, so the blit is colour-neutral; correct
encoding comes with the display path (M3).

**D17. Leftovers.** The rename and the env API are small tasks on their repos' `m1b` branches;
System32 loading lands with dvv-gpu's move to dvv-platform.

### 4.5 `dvv::gpu::Presenter` (`include/dvv/gpu/presenter.h`)

```cpp
namespace dvv::gpu {

namespace detail { class PresenterCore; struct Access; }

struct PresentFrameInfo {
    platform::PixelSize extent;  // swapchain extent: render at this size for a 1:1 blit
    VkFormat format;             // swapchain format (informational; the blit converts)
    std::uint64_t frameNumber;   // 0, 1, 2, ... per provider call
    // True only when the previous provider call's frame was submitted and completed (its record
    // function ran). False after a dropped frame, a provider error, and for the first call.
    bool previousFrameCompleted;
};
// `image` is blitted to the swapchain image (linear scaling when sizes differ and the format has
// SAMPLED_IMAGE_FILTER_LINEAR, else nearest). It must belong to this context, have TRANSFER_SRC
// usage and a format with BLIT_SRC (e.g. R8G8B8A8_UNORM). `record` (may be empty) runs first in
// the same submission. Both are released on the presenter thread once the submission has
// completed.
struct PresentFrame {
    RecordFunction record{};
    std::shared_ptr<GpuImage> image{};
};
// Called on the presenter thread, at most once per frame and never while a frame is in flight (so
// one image can be reused). Must not block long (a new image on resize is fine). An error skips
// the frame and goes to onError. The provider is called before the acquire: the record function of
// a dropped frame is destroyed without running (see PresentFrameInfo::previousFrameCompleted).
using FrameProvider = std::move_only_function<Result<PresentFrame>(const PresentFrameInfo&)>;
// Called on the presenter thread; the GUI forwards it (e.g. wx CallAfter).
using PresenterErrorHandler = std::move_only_function<void(const Error&) noexcept>;

struct PresenterOptions {
    platform::NativeWindow window{};  // must outlive the presenter
    platform::PixelSize extent{};     // current client size in physical pixels (a hint)
    bool visible = true;
    FrameProvider frames{};
    PresenterErrorHandler onError{};
    std::string name = "presenter";   // debug names and log lines
};
struct PresenterStats {
    std::uint64_t framesPresented = 0;
    std::uint64_t frameErrors = 0;          // frames skipped (provider error or unusable image)
    std::uint64_t swapchainsCreated = 0;    // first creation included
    platform::PixelSize presentedExtent{};  // of the latest presented frame
    bool hidden = false;                    // not visible, extent 0, or surface extent 0
    bool failed = false;                    // stopped presenting; see failure()
};

// Presents to one native window on its own thread (spec §4): acquire, hand the frame's commands to
// the submit thread, present, recreate the swapchain on resize/out-of-date/suboptimal. Created by
// ExecutionContext::createPresenter(); keeps the context alive. resize, setVisible, requestFrame
// and stats may be called from any thread.
class Presenter final : public Managed<Presenter> {
public:
    Presenter(CreationKey<ExecutionContext> key, std::shared_ptr<ExecutionContext> context,
              std::unique_ptr<detail::PresenterCore> core) noexcept;
    // Waits for the frame in flight (about one frame) and queue idle, destroys swapchain and
    // surface. Destroy it before the window. On Windows the wait dispatches cross-thread sent
    // messages only (5.5).
    ~Presenter();
    void resize(platform::PixelSize extent) noexcept;  // hint; latest wins; requests a frame
    void setVisible(bool visible) noexcept;  // hidden: no frames, no acquires; requests a frame
    void requestFrame() noexcept;                      // coalesced until the next frame starts
    [[nodiscard]] PresenterStats stats() const;
    [[nodiscard]] std::optional<Error> failure() const;  // why presenting stopped
    [[nodiscard]] const std::shared_ptr<ExecutionContext>& context() const noexcept {
        return context_;
    }

private:
    friend struct detail::Access;
    // `context_` is declared before `core_` on purpose: the core (thread, swapchain, surface) is
    // destroyed first, while the device and instance are alive.
    std::shared_ptr<ExecutionContext> context_;
    std::unique_ptr<detail::PresenterCore> core_;
};

}  // namespace dvv::gpu
```

## 5. Threading and the resize/minimise handshake

### 5.1 Threads and who touches what

| Thread | Presentation duties | Never |
|---|---|---|
| GUI (wx main) | creates and destroys the presenter; calls `resize`, `setVisible`, `requestFrame` (non-blocking: they set fields under the presenter mutex and notify) | touches the surface, swapchain, fence or queue |
| Presenter (one per viewport, `std::jthread` in `PresenterCore`) | surface caps, swapchain create/destroy, acquire + fence wait, provider call, `vkQueuePresentKHR` and `vkQueueWaitIdle` (both under `DeviceCore::lockQueue()`) | records commands, submits work |
| Submit (context) | records the provider's commands plus `presentBlit` and submits them (unchanged code path, `ctx->submit`) | acquires, presents |
| Waiter (context) | posts the submission's completion to the presenter's mailbox executor (unchanged) | – |

`PresenterCore` holds the surface, swapchain, images, extent, format, one acquire `VkFence`,
`PresenterLogic`, a mailbox (`detail::PresenterMailbox : IExecutor`; `post` pushes under the
presenter mutex and notifies, never inline) and the shared request block `{PixelSize extent; bool
visible; std::uint64_t requestSeq; bool stop}` plus stats and failure, under one mutex and condition
variable. **Every** `resize`, `setVisible` and `requestFrame` increments `requestSeq` (so
`setVisible(true)` requests a frame). The logic keeps `servedSeq`: `frameStarted()` stores the
`requestSeq` of the snapshot used for that provider call, and a frame is pending while `requestSeq >
servedSeq`. Presenter-internal re-requests (after a swapchain creation, after a present
OUT_OF_DATE) are a logic-owned bool that the copy never touches. A frame is awaited by an internal
fire-and-forget coroutine (`detail::FrameJob`: `suspend_never` initial/final suspend, body in
try/catch) running `co_await ctx->submit(mailbox, record)`; it resumes on the presenter thread.
`SubmitOperation::await_suspend` may throw `std::bad_alloc`: the catch reports
`frameCompleted(Errc::OutOfMemory)` (→ Failed), so stop never waits forever. The thread never exits
while a frame is in flight, so the coroutine is never destroyed while suspended (`SubmitOperation`
contract).

### 5.2 The presenter loop (binding)

```
loop:
  lock; wait until stop || mailbox non-empty || (logic says work is due) || retry deadline passed
       (when stop is set and a frame is in flight, wait only for "mailbox non-empty")
  copy request block into logic (setRequests(extent, visible, requestSeq, stop));
  take mailbox items; unlock
  run mailbox items (frame completions -> step 6)
  action = logic.next()
  Exit              -> teardown (5.5); return
  Wait              -> continue
  WaitAndRetry      -> set retry deadline now + 10 ms; continue
  RecreateSwapchain -> 5.3
  RenderFrame       -> steps 1-5 below
  Present           -> step 6 (when a completion arrived)
```

**RenderFrame** (phase Idle, visible, extent non-empty, swapchain valid and current):
1. `frame = provider({swapchainExtent, format, n++, logic.previousFrameCompleted()})`. An error:
   `onError`, `frameErrors++`, the request counts as served (`logic.frameSkipped()` stores the
   snapshot's `requestSeq` as `servedSeq`), stay Idle (nothing acquired yet, nothing leaks).
2. Check `frame.image` (present, same device, TRANSFER_SRC, format with BLIT_SRC, cached per
   format together with SAMPLED_IMAGE_FILTER_LINEAR for the blit filter); failure is `Internal`,
   handled as in step 1.
3. `vkAcquireNextImageKHR(swapchain, 100 ms, VK_NULL_HANDLE, fence, &index)`: `SUCCESS` → go on;
   `SUBOPTIMAL_KHR` → go on, recreate after this frame; `TIMEOUT`/`NOT_READY` → drop the frame,
   WaitAndRetry; `ERROR_OUT_OF_DATE_KHR` → mark recreate, keep the request, loop (a 4th one in a
   row without success marks the surface hidden until the next GUI event, i.e. the logic stores
   `requestSeq` and stays hidden until it changes: no spinning while minimised);
   `ERROR_SURFACE_LOST_KHR` → Failed (5.4); `ERROR_DEVICE_LOST` → Failed; other → Failed
   (converted). A dropped frame's record function is destroyed without running, so the next
   `PresentFrameInfo` has `previousFrameCompleted == false`.
4. Wait for the fence in 100 ms slices, reset it; `DEVICE_LOST` → Failed. **Binding:** once an
   acquire returned SUCCESS or SUBOPTIMAL, the thread waits for the fence until it signals or
   `DEVICE_LOST`, **also when `stop` is set** (stop is acted on only after the wait). Overall cap
   5 s, then Failed (`Internal` "acquire fence did not signal"); the fence is then leaked, not
   destroyed.
5. `logic.frameStarted()` (stores the snapshot's `requestSeq` as `servedSeq`; a `requestFrame()`
   that arrived during the provider call or the acquire stays pending); phase InFlight; start a
   `FrameJob` with `record = [client, image, swap = images[index], extent](CommandRecorder& r) {
   if (client) client(r); Access::presentBlit(r, *image, swap, extent); }`.

**Step 6, completion** (mailbox item with `Result<std::uint64_t>`); phase back to Idle.
- **Error:** → Failed with the frame's error (`onError` once). This covers `DeviceLost`,
  `Internal` and `OutOfMemory` (including a throwing `await_suspend`, reported by `FrameJob`'s
  catch).
- **Success:** under `lockQueue()`, `vkQueuePresentKHR({swapchain, index})` with no wait
  semaphores: `SUCCESS` → `framesPresented++`, `presentedExtent` set; `SUBOPTIMAL_KHR` → counted,
  recreate next; `ERROR_OUT_OF_DATE_KHR` → recreate and the logic-owned internal re-request;
  `ERROR_SURFACE_LOST_KHR` → Failed (5.4); `DEVICE_LOST`/other → Failed.
- Ordering and visibility: the host waited for the frame's timeline value; the transition to
  `PRESENT_SRC_KHR` makes the writes available and present makes them visible automatically.

### 5.3 Swapchain (re)creation rules

Only in phase Idle (D5); needed when there is no swapchain, out-of-date/suboptimal was seen, or
**the hint changed since the last creation** (the logic stores the hint used at creation; a hint
that never equals `currentExtent` does not re-trigger).
1. `caps = vkGetPhysicalDeviceSurfaceCapabilitiesKHR`; extent = `caps.currentExtent`, or the hint
   clamped to `[minImageExtent, maxImageExtent]` when that is `0xFFFFFFFF`.
2. Extent 0 → `logic.surfaceHidden()`: keep the old swapchain and the request; the logic stores
   `requestSeq`, and the next `resize`/`setVisible`/`requestFrame` (a new `requestSeq`)
   re-evaluates.
3. Create with the D16 format and mode, usage `TRANSFER_DST`, `EXCLUSIVE`, `preTransform =
   currentTransform`, `compositeAlpha` the first of OPAQUE/INHERIT, `clipped`, `oldSwapchain =
   current`. `ERROR_SURFACE_LOST_KHR` → Failed (5.4); `NATIVE_WINDOW_IN_USE_KHR` and others →
   Failed.
4. Old swapchain: `vkQueueWaitIdle` under `lockQueue()`, then destroy it (D7). Fetch and debug-name
   the images (`<name> swapchain image <i>`); `swapchainsCreated++`; `logic.swapchainCreated(...)`
   stores the hint used and sets the logic-owned internal re-request.

### 5.4 Surface lost, and 5.5 stop

Surface lost: `SurfaceLost` from acquire, present or swapchain creation → Failed, `Internal` "the
window's Vulkan surface was lost (was the window destroyed before its presenter?)". There is no
recovery: on Win32/Xlib a lost surface means the window is gone, which is a programming error;
replacing the presenter is the recovery (Future F14).

Stop (destructor): the GUI thread sets `stop` and notifies. On Windows `~Presenter` then loops on
`MsgWaitForMultipleObjectsEx(1, &threadHandle, INFINITE, QS_SENDMESSAGE, 0)` +
`PeekMessageW(&msg, nullptr, 0, 0, PM_NOREMOVE | PM_QS_SENDMESSAGE)` until the thread has ended
(this dispatches only cross-thread sent messages, e.g. from DXGI-based WSI, and no posted wx
events), then joins. On Linux it joins directly. The thread first finishes a pending acquire-fence
wait (5.2 step 4: also when `stop` is set, capped at 5 s, after which the fence is leaked, not
destroyed), keeps looping while a frame is in flight (its completion is not presented), then runs
`vkQueueWaitIdle` under `lockQueue()`, destroys swapchain, surface and fence, and exits; the mailbox
dies after it. The GUI blocks for about one frame plus the queue-idle wait: acceptable at window
close, documented.

### 5.6 GUI handshake (rawreel `VulkanViewport`)

| wx event | Call |
|---|---|
| frame shown → `CallAfter(startPresenting)` | GTK: `gtk_widget_realize`, then `gdk_window_ensure_native(GTKGetDrawingWindow())`. Builds the `NativeWindow` and `createPresenter({window, ToPhys(GetClientSize()), IsShownOnScreen(), provider, onError})` |
| `wxEVT_SIZE` (viewport) | `resize(ToPhys(GetClientSize()))` |
| `wxEVT_ICONIZE` (top-level, forwarded) | `setVisible(!event.IsIconized())` |
| `wxEVT_SHOW` (top-level) | `setVisible(event.IsShown())` |
| `wxEVT_PAINT` | `wxPaintDC dc(this); requestFrame()` (background style `wxBG_STYLE_PAINT`; GTK: double buffering off for the widget) |
| `onError` (presenter thread) | `CallAfter` (wrapped in try/catch, because the handler is `noexcept` and `CallAfter` allocates; a failure is logged) → log, and on failure show the message in the viewport (status text) |
| frame close | destroy the viewport (its destructor resets the presenter first), then the frame |

Binding: `~VulkanViewport` resets the presenter before anything else, so no `CallAfter` targets a
dying handler.

Startup: on Windows the entry point is `int wmain(int, wchar_t**)` with the link option
`/ENTRY:wmainCRTStartup` (`WIN32_EXECUTABLE` would otherwise expect `WinMain`) and
`wxIMPLEMENT_APP_NO_MAIN(App)`; the arguments are converted to UTF-8 (e.g.
`wxString(wargv[i]).utf8_string()`) before `parseArguments`, and wx starts with `wxEntry(argc,
wargv)`. On Linux it is `main`, which calls `XInitThreads()` and `setEnvironment("GDK_BACKEND",
"x11")`. Both parse the arguments **before** `wxEntry`. On Linux with `--selftest` and no `DISPLAY`,
`main` returns 77 (or 4 with `DVV_REQUIRE_GPU=1`) without calling `wxEntry` (GTK init would fail
inside it, and `wxEntry` would return -1). Then `main` adds a `StderrSink` and calls `wxEntry`. The
App's exit code (4/6/77) is kept in a static that `main` reads after `wxEntry` returns, because a
failing `OnInit` makes `wxEntry` return -1. `App::OnInit`: `GpuRegistry::create({.applicationName = "rawreel",
.windowSystem = defaultWindowSystem()})`, `bestDevice()` with `optional.swapchain`,
`createContext(id, {.pipelineCacheFile = defaultPipelineCacheFile(...), .presentation = true})`. A
failure shows a modal `wxMessageBox` and exits 4 (`--selftest`: stderr, 4 or 77). After `wxEntry`
returns (context and registry released in `OnExit`), `main` returns `finishWithLeakCheck(code)`.

**Selftest script** (50 ms wxTimer; each step has a 5 s deadline; a miss exits 6 naming the step):
(1) `framesPresented ≥ 2` and `presentedExtent == ToPhys(viewport size)`; (2) `SetClientSize`
800×600, then 333×177: each presents at the new extent with `swapchainsCreated` increased;
(3) `Iconize(true)` (Windows) or `Hide()` (Linux): after 300 ms `framesPresented` unchanged (one
in-flight frame tolerated), `hidden`, not `failed`; (4) restore: a new frame; (5) close, then
`validationMessageCount() == 0`, `failure()` empty, leak check passes.

### 5.7 `PresenterLogic` (pure; binding behaviour, signatures indicative)

```cpp
namespace dvv::gpu::detail {
enum class VkOutcome : std::uint8_t { Success, Suboptimal, OutOfDate, Timeout, SurfaceLost,
                                      DeviceLost, OtherError };
class PresenterLogic {
public:
    enum class Action : std::uint8_t { Wait, WaitAndRetry, RecreateSwapchain, RenderFrame, Present,
                                       Exit };
    // request_seq: the GUI request counter of 5.1 (every resize, setVisible, requestFrame).
    void setRequests(platform::PixelSize extent, bool visible, std::uint64_t request_seq,
                     bool stop) noexcept;
    // Stores the hint used for this creation; sets the logic-owned internal re-request.
    void swapchainCreated(platform::PixelSize extent) noexcept;
    void surfaceHidden() noexcept;  // stores requestSeq; hidden until it changes
    void acquired(VkOutcome outcome) noexcept;
    // -> InFlight; servedSeq = the requestSeq of the snapshot used for the provider call.
    void frameStarted() noexcept;
    void frameSkipped() noexcept;  // provider or image error: request served, stays Idle
    void frameCompleted(std::optional<Errc> error) noexcept;  // an error -> failed
    void presented(VkOutcome outcome) noexcept;
    [[nodiscard]] Action next() const noexcept;
    [[nodiscard]] bool failed() const noexcept;
    [[nodiscard]] bool hidden() const noexcept;
    [[nodiscard]] bool previousFrameCompleted() const noexcept;  // for PresentFrameInfo
};
}
```
Behaviour (each a unit-test case): (1) no RenderFrame while hidden or 0-sized; the request is
served once visible; (2) several resizes → one recreation at the latest hint; a hint that never
equals `currentExtent` gives one recreation per hint change; (3) requests during a frame in flight →
exactly one more frame; (4) OutOfDate (acquire or present) and Suboptimal → RecreateSwapchain before
the next RenderFrame; (5) four OutOfDates in a row → hidden until a GUI event (a new `requestSeq`);
(6) Timeout → WaitAndRetry; (7) SurfaceLost → failed; (8) DeviceLost → failed, then only Exit;
(9) completion error → failed; (10) stop while InFlight → Wait until completion, then Exit, no
Present; (11) stop while Idle → Exit; (12) a request during provider/acquire is not lost
(`requestSeq` grew after the snapshot → one more frame); (13) a snapshot without a new event keeps
hidden; (14) dropped frame → the next info has `previousFrameCompleted == false`; (15) stop during
the acquire wait: no Exit before the fence wait ends (signal, `DEVICE_LOST`, or the 5 s cap →
Failed, fence leaked); a core case, exercised by §8.2 case 7.

## 7. Error handling

All Vulkan results go through the existing `vkCheck`/`errcOf` mapping in dvv-gpu (§11). The WSI
results the table does not list (`ERROR_SURFACE_LOST_KHR`, `ERROR_NATIVE_WINDOW_IN_USE_KHR`) fall
into "any other error → `Internal`". Recoverable results are handled and never become errors.

| Situation | Where | `Errc` / behaviour |
|---|---|---|
| `windowSystem` set, but the loader lacks surface extensions | `GpuRegistry::create` | `Unsupported` (vk-bootstrap check) |
| `presentation` without a window system on the registry | `createContext` | `Internal` |
| Device without `VK_KHR_swapchain` with `presentation` | `createContext` | `Unsupported` |
| `createPresenter` on a context without presentation; empty provider; `NativeWindow` of another window system or `monostate` | `createPresenter` | `Internal` |
| Surface creation failed | `createPresenter` | `errcOf(result)`: `EXTENSION_NOT_PRESENT` → `Unsupported`, OOM → `OutOfMemory`, `INITIALIZATION_FAILED` → `Unsupported`, `NATIVE_WINDOW_IN_USE` → `Internal` |
| Queue family cannot present to the surface; no usable format (TRANSFER_DST usage + BLIT_DST) | `createPresenter` | `Unsupported` |
| Thread start fails | `createPresenter` | `std::system_error` → `Internal`; `bad_alloc` → `OutOfMemory` |
| Provider returns an error | presenter thread | that error, passed through to `onError`; frame skipped |
| Image unusable for the blit | presenter thread | `Internal` to `onError`; frame skipped |
| Recording or submission fails | presenter thread | the submission's error, Failed (`onError` once); a throwing `await_suspend` → `OutOfMemory`, Failed |
| Acquire/present `TIMEOUT`, `NOT_READY`, `SUBOPTIMAL`, `OUT_OF_DATE`; surface extent 0 | presenter thread | not an error (5.2–5.3) |
| Surface lost (acquire, present or swapchain creation) | presenter thread | `Internal` "the window's Vulkan surface was lost (was the window destroyed before its presenter?)", Failed |
| Acquire fence did not signal within 5 s | presenter thread | `Internal` "acquire fence did not signal", Failed (fence leaked) |
| `ERROR_DEVICE_LOST` anywhere | presenter thread | `DeviceLost`, Failed (recovery in M3) |
| Swapchain creation `OUT_OF_*_MEMORY` | presenter thread | `OutOfMemory`, Failed |
| `DynamicLibrary::open`: missing/unloadable → `Unsupported`; empty name or path with `SystemDirectory` → `Internal`. Loader missing (System32 only on Windows) → `Unsupported` "Vulkan loader not found (...)" | dvv-platform / dvv-gpu | as stated |
| `TestWindow` without a display; env API invalid input | testing / dvv-base | `Unsupported` "no display" (test exits 77); `false`/`nullopt` |
| GUI startup GPU failure | rawreel-gui | modal dialog + exit 4 (`--selftest`: stderr, exit 4 or 77) |

Failed is terminal for a presenter: `stats().failed`, `failure()` is set, and `onError` is called
once with the error. The GUI shows the message in the viewport. Replacing the presenter (or, in M3,
the device) is the recovery.

2. **Resize** 320×240 → 640×480 → 97×61 → 640×480: each step presents at the new extent;

5. **Provider error** reaches `onError` once, `frameErrors++`; the next good frame presents.
6. **Bad image** (no TRANSFER_SRC): `Internal` to `onError`, no validation message.
7. **Stop in flight:** destroy right after `requestFrame()`, 20 times: no hang, leak or message.
8. **Two presenters** on two windows, one context, concurrently for 1 s (the TSan target).
9. **Error paths:** no-presentation context, `monostate` window → `Internal`; headless registry
   with `presentation` → `Internal` from `createContext`.
10. **Leak check:** the live count returns to 0.

Surface-lost and device-lost cannot be provoked reliably: covered by `PresenterLogic` cases 7–8 and
review (as M1a did for its out-of-memory paths).
