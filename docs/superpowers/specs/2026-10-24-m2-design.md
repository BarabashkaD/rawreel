## 1. Scope and exit criterion

**Exit criterion (spec §15 M2, made concrete):**
1. `rawreel-cli info <uri> [--json]` prints the source description of a raw file, a Y4M file or a
   synthetic source.
2. `rawreel-cli dump <uri> --frame N [--count K] [--view original|planes] [--via cpu|gpu] --out
   <file>` writes the original bytes (Exact) or the unpacked planes (Lossless); `--via cpu` and
   `--via gpu` give byte-identical files, and the converter stats (`dump --json`) prove the path:
   `--via gpu` has `GpuUnpack.runs > 0` (planes) / `Upload.runs > 0` (original), `--via cpu` has no
   GPU converter runs (§4.6).
3. **GPU unpack is bit-exact for every format of the M2 catalogue** (§2 D3: 37 formats): for each
   format, sizes 1×1, 2×2, 33×17, 49×3 and 64×64 (v210: 2×2, 34×17, 50×3 and 64×64 — sizes rounded
   up to its `widthMultiple` 2, 1×1 skipped), two noise seeds, the GPU unpack of the CPU
   reference pack equals the source code values, with zero validation messages, on lavapipe (CI,
   WSL) and on local NVIDIA hardware. Every format also has a hand-derived layout golden (D4), and
   v210 has the partial-group goldens 2×1 and 4×1.

**In scope**
- **dvv-media (new repo):** value types (§6.1), pixel-format descriptor + 37-format catalogue + CPU
  reference pack/unpack, custom formats as JSON (Task 3b, D3), `IFrame` + 4 implementations,
  `FrameStore` (trimmed API, §4.4), 5 converters,
  generic GPU unpack shader, `ISource`/`ISourceProvider`/`SourceFactory`, providers synthetic, raw and
  Y4M (in a component library inside dvv-media, D1).
- **dvv-platform:** `FileReader` (unbuffered positional reads, buffered fallback; Windows overlapped
  handle with blocking waits) (D8).
- **dvv-registry:** kind↔interface check (`dvv::InterfaceKind<I>`, D14).
- **dvv-gpu:** images in shaders via Vulkan 1.4 push descriptors (D6): image views, a dispatch
  overload with storage images, three more required features.
- **rawreel:** `rawreel-cli` with `info`, `dump`, `bench` (minimal, D18), `--version`, `--help`.
- **rawreel-workspace:** wiring of dvv-media, spec updates. **No new third-party dependency.**

**Deferrals (decided by the arbiter; details in §2 "Deferral decisions"):**
- Custom formats as JSON: **not deferred** (JSON + CLI in M2, Task 3b); the editor dialog → M3.
- Bindless heap → replaced by push descriptors (D6); a heap only if ever needed → v1.x (F12).
- Specialisation-constant fast paths → when measured (trigger: `bench`, D18).
- IOCP/io_uring async reads, mmap + `MappedFrame` → v1.x (M3 if the D18 rule triggers); the
  overlapped handle with a blocking wait is in M2 (D8).
- Sharded store index → when measured. Cancellation → M3 (with the hook of D10). Prefetch policy → M3
  (`pin()` stays). `VK_EXT_memory_budget` budgets → M3 (Preferences). Image pooling → when measured
  (F10).
- `ToDisplay` + colour engine → M3. Media clock → M3.
- `IFormatDetector` component kind → with the second detector (v1.x).
- Upload benchmark → minimal `bench` in M2 (D18).
- `AVPixelFormat` mapping and the FFmpeg `extractplanes` oracle → M4 (FFmpeg arrives there).

**Inherited by M3** (also written into spec §15 by Task 15): `ToDisplay` + colour engine, media
clock, prefetch with cancellation, `VK_EXT_memory_budget` budgets, the custom-format editor dialog,
and any item triggered by the `bench` rule (D18).

## 2. Decisions

**D1. Built-in core sources live in dvv-media as a component library, not in dvv-components.**
Target `dvv_media_sources` (static, alias `dvv::media_sources`) holds the synthetic, raw and Y4M
providers, each `DVV_REGISTER(dvv::media::ISourceProvider, …)`, linked with M1a's
`dvv_link_components()`. Reason: dvv-media's own tests need `SyntheticSource` fixtures (§12: tiny
frames from `SyntheticSource`), and dependencies point downward only. Alternatives: create
dvv-components now with `dvv_add_component()` (one more repo and the deferred CMake function before
anything needs per-component options; it starts in M4 with metrics and FFmpeg/lavfi); put the sources
in dvv-media without registration (breaks "source components are registered as providers", §7.2).
Spec §3.1 text changes ("dvv-media: … core source providers").

**D2. One descriptor model: per-plane pixel groups with sample slots.** A plane is a row of
*groups*; a group spans `groupPixels` full-resolution pixels in `groupBytes` bytes made of `words`
of `wordBytes` (1, 2 or 4) with one endianness; each sample of the group is a slot `{component,
index in the component's own grid, word, shift}`, value = `(word >> shift) & mask(bits)`. This one
rule covers planar (yuv420p10le: 1-pixel group, one 16-bit LE word, shift 0), semi-planar (p010le UV:
2-pixel group, two 16-bit words, shift 6), packed (yuyv422: 2-pixel group, 4 one-byte words), 16-bit
BE (rgb48be) and bit-packed (v210: 6-pixel group, four 32-bit LE words, 3 slots each;
x2rgb10le). Row bytes = `ceil(width / groupPixels) · groupBytes`, rounded up to `rowAlign` (1, or
128 for v210); plane rows = `ceil(height / 2^subY)`. This matches FFmpeg's `av_image_fill_linesizes`
with alignment 1 (rawvideo files) for every catalogue entry, and FFmpeg's v210 decoder stride
(`ceil(w/48)·128`). A descriptor field `widthMultiple` (default 1; v210: 2) rejects widths FFmpeg's
encoder rejects: `geometry()` returns `Format` "v210 needs a width that is a multiple of 2". Alternatives: FFmpeg's `AVComponentDescriptor` (step/offset/shift/depth) cannot
express v210 (FFmpeg treats v210 as a codec); special code per layout class (more code, more bugs,
two implementations of each class in C++ and Slang).

**D3. The M2 catalogue is 37 formats, all bit-exact.** Gray: `gray gray10le gray12le gray16le
gray16be`. Planar YUV: `yuv420p yuv422p yuv444p yuv420p10le yuv422p10le yuv444p10le yuv420p12le
yuv422p12le yuv444p12le yuv420p16le yuv444p16le yuv420p10be`. Semi-planar: `nv12 nv21 p010le p016le`.
Packed YUV: `yuyv422 uyvy422 y210le v210`. Packed RGB: `rgb24 bgr24 rgba bgra argb rgb48le rgb48be
rgba64le x2rgb10le`. Planar RGB: `gbrp gbrp10le gbrp16le`. Every layout class of §7.3 (planar,
semi-planar, packed, 8–16 bit, LSB/MSB-aligned, both endiannesses, bit-packed groups, alpha) has at
least one member, so further pix_fmts (abgr, rgb0, yvyu422, nv16, p210le, yuva*, gbrap, …) are one
table line plus one golden each, added when needed. Names are FFmpeg `pix_fmt` names; `v210` is
FFmpeg's codec name (no pix_fmt exists). **Custom formats as JSON** (§7.3, a v1 requirement):
**not deferred** — `format_json.{h,cpp}` (Task 3b) serialises and parses descriptors (`formatToJson`,
`formatFromJson` validates incl. the GPU limits and interns; a name equal to a catalogue name is
`Format`); raw URIs accept `fmt=@<path to .json>` and `info --json` prints the descriptor. The
**editor dialog** is M3 (format dialog). Custom matrices arrive with M3, so `ColourId` interning stays.

**D4. Bit-exactness is checked against two things.** (a) GPU unpack == CPU reference unpack == the
code values the test generated (GPU of `pack(x)` gives `x`); (b) a hand-derived **layout golden** per
format: a tiny frame (2×2, or 6×1 for v210, plus the v210 partial-group goldens 2×1 and 4×1 from
`v210_template.c`) with distinct code values and its expected packed bytes,
written from FFmpeg's `pixdesc.c`/`v210dec.c` definitions as literal arrays in the test (small test
data, not committed fixture files, §12). (a) alone would accept a wrong table entry (CPU and GPU share
the descriptor); (b) catches it. FFmpeg's `extractplanes` oracle (§12) joins in M4.

**D5. Unpacked planes:** one image per component (padding is not content), `R8_UINT` for ≤ 8 bits,
`R16_UINT` for 9–16 bits, at the component's subsampled size, LSB-aligned code values, layout
`GENERAL` at rest (written as storage images, read by later analysers as storage or sampled images;
§6.3 "rests in one read layout"). The host form of the same view is planar, tight, little-endian,
8- or 16-bit containers, planes in component order (Y U V A / R G B A / Y) — for v210 this is
byte-identical to an FFmpeg `yuv422p10le` frame, which makes `dump --view planes` checkable by hand.
The unpacked format is a derived descriptor `unpackedFormat(f)` interned next to the catalogue.

**D6. (spec change, accepted) Images reach shaders through push descriptors, not a bindless heap.**
Vulkan 1.4 makes push descriptors core and mandatory (`vkCmdPushDescriptorSet`,
`maxPushDescriptors ≥ 32`). A compute pipeline declares how many storage images it binds (set 0,
bindings 0..n-1, `PUSH_DESCRIPTOR` layout); `CommandRecorder::dispatch` gets an overload taking the
images, checks them, moves them to `GENERAL` itself (tracked like every `GpuImage`) and pushes their
descriptors. Gains: no heap, no slot allocator, no slot retirement, none of the update-after-bind
features, and synchronization validation **sees** image accesses (it cannot see the bindless indices
or buffer addresses, §16). "No per-frame descriptor sets" (§5.4) still holds. Cost: at most a few
descriptor writes per dispatch (unpack 1; M4 metrics ≤ 8, below the 32 limit). Alternative (spec
§5.4 literal, keep as fallback R2): a context-wide heap (`STORAGE_IMAGE[4096]`, `SAMPLED_IMAGE[4096]`,
update-after-bind, partially bound, unused-while-pending), slots per image freed through the retire
queue, an installed `bindless.slang`; about one extra L task. **Decided: push descriptors** (both
reviewers and the arbiter); spec §5.4/§5.1/§3.1 are updated in Task 15; a bindless heap is F12 (v1.x
if ever).

**D7. One generic unpack shader** driven by push constants computed from the descriptor; one
dispatch per output component. **Specialisation-constant fast paths** (§5.4): deferred, when measured
(trigger: the `bench` rule of D18).

**D8. File reading is a concrete handle with blocking positional reads; callers run it on an I/O
thread pool.** `dvv::platform::FileReader` (move-only, like M1b's `DynamicLibrary`): Windows
`CreateFileW` with `FILE_FLAG_OVERLAPPED` (plus `FILE_FLAG_NO_BUFFERING` when unbuffered); `readAt` issues
`ReadFile` with a per-call `OVERLAPPED` and its own event (low bit set, no IOCP) and blocks in
`GetOverlappedResult(…, TRUE)`, so concurrent reads are not serialised by the handle;
`ERROR_HANDLE_EOF` = short read. Linux `open(O_DIRECT)` + `pread`. If unbuffered opening fails (9p/drvfs
in WSL, some network shares) it reopens buffered and says so (`unbuffered() == false`). **Probe at
open:** after an unbuffered open succeeds and the file is not empty, `open` reads the first
`alignment()` bytes; `EINVAL`/`ERROR_INVALID_PARAMETER` → reopen buffered, debug log. `readAt` never
reopens (it stays `const` and thread-safe); a misaligned call stays `Internal`. Asynchrony is `co_await
resumeOn(io_pool)` in the caller (§4 "Linux `O_DIRECT` thread pool" – the same on Windows). The README
states the open flags. **Deferred:** IOCP/io_uring async reads and the mmap fallback with
`MappedFrame` → v1.x (spec §16 "mmap fallback: v1.x"); M3 if the `bench` rule of D18 names the
produce stage. Spec §3.1/§4/§10.4 replace `IAsyncFileReader` by `FileReader`.

**D9. Read path: aligned host buffer, then a copy into staging.** A raw frame is read into an
aligned `HostFrame` (the read covers the aligned range around the frame; the frame starts at an offset
inside), and `HostToStaging` copies it into a mapped `HostUpload` buffer. Reading straight into mapped
Vulkan memory with `O_DIRECT`/`NO_BUFFERING` is not reliable (BAR or write-combined memory). The extra
memcpy is ~2–5 ms per 4K 10-bit frame (24.9 MB), on the CPU pool, reported by `bench`. Zero-copy into
staging is Future F3.

**D10. FrameStore simplifications for M2** (all internal; the public API is §4.4):
- **One store mutex**, not a sharded index. **Deferred:** shards when a profile shows contention
  (when measured).
- **GPU conversions complete before an entry is published**: a converter `co_await`s its submission,
  so every published view's `ready` `SyncPoint` is already reached. No `lease.retire(lastUse)`: a
  lease keeps its resources alive by shared ownership, and a reader captures the lease (or its
  `shared_ptr<GpuImage>`) in its record function, exactly the M1a `ResourcePool` rule (§5.3). The
  `SyncPoint` stays in the data model for later pipelining.
- **Cancellation** (`stop_token`) **deferred → M3**. Reason: scope; the player is its first user.
  Hook: waiters are removable nodes and pending creations count their waiters, so M3 adds a
  `std::stop_token` parameter without restructuring the single-flight code.
- **Prefetch policy** (adaptive, direction-aware, §4) **deferred → M3** with the player; M2 has `pin()`
  and "pinned entries are never evicted".
- **Budgets from `VK_EXT_memory_budget`** **deferred → M3** (Preferences); M2 takes budgets from
  `FrameStoreOptions` with fixed defaults.
- **Out of memory:** a failed allocation evicts the tier to half its budget and retries once (§11
  table), then reports `OutOfMemory`.
- **No image pooling** (**deferred, when measured**, F10; spec §15 deferral "images in ResourcePool:
  M2" becomes "when measured"): entries are cached and evicted as wholes; per-frame image allocation
  is measured by `bench`; pooling only if it shows.

**D11. Sources are attached to the store explicitly.** `FrameStore::attach(shared_ptr<ISource>)`
returns the origin id and `detach(origin)` releases it. The store must reach the producer of a
missing original (§7.1 "the store's producer for its `FrameKey.origin`"), and the trimmed API has no
entry point for that. The store holds the source; the source never holds the store (it gets it only
through `ProduceContext` during `produce`), so there is no cycle.

**D12. Every requester resumes on its own executor** (spec §6.5; the same form as dvv-gpu's
`submit(IExecutor& resume_on, …)`). `acquire(key, want, IExecutor& resume_on, where)`, and the same
parameter on `acquireOriginal` and `pin`. Joiners of a pending creation and the first requester are
posted to their `resume_on`, never resumed inline; `resume_on` must outlive the operation. The store
does `co_await resumeOn(cpu)` before every Produce; file sources hop to `io` themselves.
Alternative: resume on the store's CPU executor (the draft); rejected (against spec §6.5, data races
in the M3 Session).

**D13. Converters in M2:** `HostToStaging`, `Upload`, `Readback` (buffer and image), `GpuUnpack`,
`CpuUnpack` (the CPU reference as a Lossless converter in the host domain: the CPU fallback of
§7.3 and the `--via cpu` path). `StagingAlias` needs no code: a `StagingFrame` in `HostReadback`
memory (made by Readback) offers both native views `HostPlanes/HostVisible` and `VkBuffer/HostVisible`;
one in `HostUpload` memory (made by HostToStaging) offers only `VkBuffer/HostVisible` (no CPU reads of
write-combined memory; spec §6.2 note in Task 15). **`ToDisplay` deferred → M3** (with the colour
engine): it needs the colour engine (§8: matrices, range, transfer), whose
only consumer and only meaningful test (the display path, swscale goldens ±1) arrive in M3/M4.
`Downscale`, `HostImageCopy`, `WrapAsAvFrame`/`AvFrameToHost` (M4), `PeerCopy` (v1.x) stay out.

**D14. Providers and keys.** A provider is a component (`Kind::Source`) implementing
`ISourceProvider { schemes(), match(), open() }`. `ISource` instances are managed objects whose
authority is `SourceFactory`; the factory passes a move-only `OpenTicket` into `open()`, and the
provider turns it into the typed key with `SourceFactory::issueKey<T>(std::move(ticket))` (a
`CreationKey` must be issued for the concrete type, which only the provider knows). Filename
detection (`<name>_WxH[_fmt][_fps]`) is a function inside the raw provider. **Deferred:** the
`IFormatDetector` component kind (§7.2, §9.3) → with the second detector (sidecar files, v1.x).
**Kind check** (spec §15 "with dvv-media"): dvv-registry gains a trait `dvv::InterfaceKind<I>`,
specialised in the interface header (`ISourceProvider` → `Kind::Source`); when specialised,
`ComponentRegistry::create(caps)` marks a component whose `info().kind` differs unavailable ("kind X
does not match interface kind Y"). The three providers get a conformance case (schema valid, `probe`
does not throw, creatable only through the registry, live count 0 after destruction); conformance for
dvv-components stays deferred in spec §15.

**D15. Y4M:** header tags `W H F I A C X…`; `C` maps to the catalogue (`420jpeg 420paldv 420mpeg2 420
→ yuv420p`, `422 → yuv422p`, `444 → yuv444p`, `mono → gray`, `420p10 422p10 444p10 420p12 422p12
444p12 420p16 444p16 → …le`, `mono16 → gray16le`; others `Unsupported`); a missing `C` tag means
`420jpeg` → yuv420p; `420jpeg/420mpeg2/420paldv` differ only in chroma siting, which M2 does not carry
(future: `ChromaLocation`, M3). `XCOLORRANGE=FULL|LIMITED`
sets the colour range. Only parameterless `FRAME\n` headers: frame `i` is at `header + i·(6 + frame
bytes)`, and each read checks the marker (`Unsupported` "Y4M frame parameters are not supported"
otherwise) — random access without an index scan. The aligned read range starts at
`alignDown(offset − 6, a)` so the marker is inside it (§5.6).

**D16. Synthetic patterns:** `gradient` (per component a diagonal ramp over the full code range,
shifted by the frame index) and `noise` (`hash(seed, index, component, x, y) & mask`, every bit
pattern). Both are scalar CPU code producing code values, packed with the CPU reference. Colour bars
for viewing wait for M3.

**D17. Media clock deferred → M3.** It exists only for the player ("advances only when the frames of
all streams are ready", §4); nothing in M2 can drive or test it.

**D18. Upload benchmark → minimal `rawreel-cli bench` (in M2).** It runs a URI through the real path
(produce → staging → upload → unpack). Per-stage numbers come from the converter stats (§4.4
`StoreStats::converters`) plus a Produce entry (bytes, time, reader mode `unbuffered`/`buffered`)
(timestamp queries are M3). `bench --inflight K` (default 4): `whenAll` of K `acquireOriginal` on
consecutive frames; it prints end-to-end frames/s and GB/s per stage. **Decision rule** (also written
into spec §16): on local NVIDIA + NVMe with 4K yuv420p10le at K=4, if end-to-end < 60 fps, the
bottleneck stage's fallback becomes an M3 item (produce < 3 GB/s → F1 overlapped/IOCP or io_uring;
upload < 3 GB/s → transfer queue; otherwise the R6 order). The universal queue (spec §17 default)
stays otherwise. Alternative: drop `bench` entirely (the alignment risk §16 is covered by tests)
— rejected because it is the only evidence for the 4K 10-bit 60 fps target before M3 builds playback
on top, and it costs ~150 lines.

**D19. `rawreel-cli` lives in the rawreel repo** (spec §3.1), next to `rawreel-gui`, with no wx
dependency (§3.2). Exit codes per §10.3; `--json` prints results and errors as JSON (`dvv::json`).
**Unicode paths:** on Windows `rawreel-cli` uses `int wmain(int, wchar_t**)` and converts the
arguments to UTF-8 (`WideCharToMultiByte(CP_UTF8, WC_ERR_INVALID_CHARS)`, a private helper in
`src/cli/`); Linux uses `main`. Every UTF-8 → path conversion (URI path, `--out`, JSON format path)
goes through `std::filesystem::path(std::u8string(...))` in one dvv-media helper, `pathFromUtf8`
(a plain `std::string` → path conversion uses the ANSI code page on Windows).

**D20. Colour is carried, not converted.** `ColourParams {matrix, range, transfer, primaries}`
(each with `Unspecified`) is interned as `ColourId`; sources fill what they know (Y4M range; `?range=`
`?matrix=` on raw/synthetic URIs); `acquireOriginal` forces the frame's own colour (§6.6).

enum class FileReadMode : std::uint8_t {
    Unbuffered,  // try FILE_FLAG_NO_BUFFERING / O_DIRECT, fall back to buffered on refusal
    Buffered,    // plain reads (small header reads, tests of the fallback)

// may run concurrently on several threads (positional reads, no shared file position).
// Windows: FILE_FLAG_OVERLAPPED (+ FILE_FLAG_NO_BUFFERING when unbuffered); each readAt uses its
// own OVERLAPPED and event (low bit set, no IOCP) and blocks in GetOverlappedResult(..., TRUE).
class FileReader {
public:
    // UTF-8 path. Errc::Io "'<path>' could not be opened: <system message>" (missing, denied, a
    // directory). The size is read once at open. Unbuffered: after the open succeeds and the file
    // is not empty, a probe reads the first alignment() bytes; EINVAL / ERROR_INVALID_PARAMETER →
    // reopen buffered (debug log).
    [[nodiscard]] static Result<FileReader> open(const std::filesystem::path& path,

    FileReader(const FileReader&) = delete;  FileReader& operator=(const FileReader&) = delete;
    ~FileReader();

    [[nodiscard]] bool unbuffered() const noexcept;     // false after the fallback
    // Required alignment of offset, length and destination address: 1 when buffered; otherwise
    // max(4096, the volume's sector size) (Windows FileStorageInfo, Linux statx STATX_DIOALIGN).
    [[nodiscard]] std::uint32_t alignment() const noexcept;
    // Blocking read of destination.size() bytes at `offset`; returns the bytes read, which is less
    // only at the end of the file. Errc::Internal for a misaligned offset, size or address;

    // reads internally; ERROR_HANDLE_EOF is a short read. Never reopens.

    [[nodiscard]] const std::filesystem::path& path() const noexcept;

// pixel_format.h
namespace dvv::media {
enum class ColourModel : std::uint8_t { Gray, Yuv, Rgb };
enum class ComponentKind : std::uint8_t { Y, U, V, R, G, B, A };
enum class ByteOrder : std::uint8_t { Little, Big };

inline constexpr std::size_t MAX_COMPONENTS = 4, MAX_PLANES = 4, MAX_SLOTS = 12;

struct ComponentDesc {
    ComponentKind kind;
    std::uint8_t bits;            // significant bits, 1..16
    std::uint8_t log2SubX = 0;    // horizontal subsampling (1 = half width, rounded up)
    std::uint8_t log2SubY = 0;
};
struct SampleSlot {
    std::uint8_t component;       // index into components
    std::uint8_t index;           // sample index inside the group, in the component's own grid
    std::uint8_t word;            // word index inside the group
    std::uint8_t shift;           // bit position of the sample's LSB inside the word
};
struct PlaneDesc {
    std::uint8_t groupPixels;     // full-resolution pixels per group (1, 2, 6, ...)
    std::uint8_t groupBytes;      // bytes per group
    std::uint8_t wordBytes;       // 1, 2 or 4; groupBytes % wordBytes == 0
    ByteOrder order = ByteOrder::Little;
    std::uint16_t rowAlign = 1;   // row stride alignment in bytes (v210: 128)
    std::uint8_t log2SubY = 0;    // rows = ceil(height / 2^log2SubY); equals its components'
    std::uint8_t slotCount = 0;
    std::array<SampleSlot, MAX_SLOTS> slots{};  // every sample of one group; other bits are padding
};
struct PixelFormatDescriptor {
    std::string name;             // FFmpeg pix_fmt name ("v210": codec name)
    ColourModel model;
    std::uint8_t componentCount;
    std::array<ComponentDesc, MAX_COMPONENTS> components;   // order = unpacked plane order
    std::uint8_t planeCount;
    std::array<PlaneDesc, MAX_PLANES> planes;
    std::uint8_t widthMultiple = 1;   // the width must be a multiple of this (v210: 2)
};
// Checks a descriptor (slots inside the group and inside their word, no overlapping bits, every
// component sample of a group present exactly once, bits <= 16, groupPixels % widthMultiple == 0,
// ...). Errc::Format with the reason.
[[nodiscard]] Result<void> validate(const PixelFormatDescriptor&);

// Process-wide tables (formats and colours): entries are heap-allocated and never moved (a vector
// of unique_ptr under a shared_mutex, or a chunked array), so descriptor()/colourParams() return
// stable references while custom formats are interned concurrently.

// <= 8 bits, else 16; named "<name>@planes". Interned on first use; idempotent for unpacked formats.
[[nodiscard]] FormatId unpackedFormat(FormatId);
[[nodiscard]] bool isUnpacked(FormatId) noexcept;

                       std::uint32_t rowBytes; };
struct FrameGeometry { std::array<PlaneGeometry, MAX_PLANES> planes; std::uint8_t planeCount;
                       std::uint64_t bytes; };           // tight layout, planes back to back
// Errc::Format for 0 width/height, a frame above 2^32 rows·bytes per plane, or a width that is not a

// Component grid size: ceil(width / 2^log2SubX) x ceil(height / 2^log2SubY).

    [[nodiscard]] StoreStats stats() const;

## 5. Threading, data flow and protocols

### 5.1 Threads

| Thread | M2 duties | Never |
|---|---|---|
| Caller (CLI main via `syncWait`; Session in M3) | `SourceFactory::open`, `attach`, `acquire*`; resumes on its own `resume_on` executor (D12) | holds a store lock across `co_await` |
| CPU pool (`options.cpu`, a `dvv::ThreadPool`) | converter bodies (`memcpy`, CPU unpack), plan execution, the hop before every Produce | blocking I/O |
| I/O pool (`options.io`, a `ThreadPool`, default 4 threads) | `FileReader::readAt` (blocking), header reads at open | GPU work |
| GPU submit / waiter (dvv-gpu) | record + submit converter commands; post completions to the CPU pool | – |

### 5.2 `acquire` (binding behaviour)

```
acquire(key, want, resume_on):
  lock
    rec = records[key] (create empty)
    if a published entry e of rec satisfies want: e.readers++; e.lastUse = tick; hits++; unlock; return lease(e)
    if a pending entry p for want exists: register waiter (resume_on) on p; unlock; co_await p
      (posted to resume_on) -> lease or error
    if want.colour != rec.desc.colour: unlock; return Unsupported   // no colour converter in M2
    if noPath cache has (original format, colour-equal, target state): unlock; return Unsupported
    plan = Dijkstra over the store's static converter graph (fixed at create: host-only or with GPU)
           with sources {Produce} ∪ rec's published AND pending entries (cost 0 for existing ones),
           target = want, depth <= maxPlanDepth
    none -> noPath cache insert (target unreachable from Produce in the static graph); unlock;
            return Unsupported "no converter path from <..> to <..>"
    insert pending entries for every step output not already present (an existing entry is never
    re-created; a step whose input is pending joins it as a waiter); misses++
  unlock
  for each step in plan:                  // never under the lock
    if the step's input is pending: co_await it (as a waiter)
    input = lease on the step's input (held until the step finishes)
    out = co_await step.run(input)        // Produce: co_await resumeOn(cpu), then source->produce(index, ctx)
                                          // (file sources hop to io themselves); ctx.publish fills the
                                          // pending original; CPU steps: co_await resumeOn(cpu);
                                          // GPU steps: co_await ctx->submit(cpu, record)
    on OutOfMemory: trim(step domain, budget/2); retry once
    lock; publish out (or remove pending + record failure); collect waiters; account tier bytes;
      update converter stats; unlock
    post each waiter's continuation to its own resume_on executor (never inline)
    on error: remaining pending entries fail with the same error (not cached); return it
  evictIfOverBudget(each touched tier)    // skipping entries with readers or pins
  post to resume_on; return lease(final entry)
```
- Satisfies: `format`, `colour`, `api`, `domain` equal; `want.layout == Any` or equal. Preference
  Exact > Lossless > Derived when several satisfy; Derived is never returned for an original-format
  request (it plans from the original instead). M2 has no Derived converter; the store tests use a
  fake one (Task 7b).
- The noPath cache depends only on `(original format, colour-equal, target state)`, never on what
  exists, so a pending original never causes a transient "no path"; it is permanent.
- A lease's destructor decrements `readers` **and** touches the LRU under the store mutex (`readers`
  is a plain integer guarded by it; the LRU touch checks a `linked` flag). Leases hold
  `shared_ptr<FrameStore>` (or its internal state) plus `shared_ptr<Entry>`, so no entry can be
  leased when the store dies.
- Eviction order inside a tier: Derived, then Lossless, then Exact entries, then LRU. Originals of deterministic
  sources are dropped freely (the source reproduces them); M2 has no non-deterministic source, so the
  spill rule (§6.5) is not built (v1.x with processors).
- `detach(origin)`: removes the source and the origin's unleased entries; leased entries die with
  their leases; a later `acquire` of that origin is `Internal` "origin N is not attached".
- Lock rules: one mutex; never held across `co_await`, `post`, `produce`, a converter body, a
  `shared_ptr<IFrame>` release that may run a destructor (frames are moved out and released after
  unlocking) or a logger call.

### 5.3 Planner

States are `(original|unpacked, Api, MemKind)`; edges are converters with a cost in bytes moved
(host copy 1×, PCIe 2×, GPU-local 0.5×; CPU unpack 4×, so the GPU is preferred for device targets and
the CPU for host targets). The converter graph is **static per store** (host-only or with GPU, fixed
at `create`): a static graph of at most 18 states. Dijkstra runs per planning call; there is no plan
cache (Dijkstra on ≤ 18 states is cheaper than the cache). Each converter keeps `ConverterStats`
(`runs`, `bytes`, `nanoseconds`; relaxed counters), reported in `StoreStats::converters`.

| Converter | From → to | Fidelity | Implementation |
|---|---|---|---|
| Produce (pseudo) | – → original HostPlanes/Host (or what the source publishes) | Exact | `source->produce` |
| HostToStaging | original HostPlanes/Host → original StagingFrame (HostUpload; offers only VkBuffer/HostVisible) | Exact | `memcpy` on cpu, then `buffer->flush()` |
| Upload | original VkBuffer/HostVisible → original VkBuffer/DeviceLocal | Exact | `copyBuffer` |
| GpuUnpack | original VkBuffer/DeviceLocal → unpacked VkImage/DeviceLocal | Lossless | §5.4 |
| Readback | VkBuffer or VkImage/DeviceLocal → HostPlanes/HostVisible (StagingFrame, HostReadback) | Exact | `copyBuffer` / `copyImageToBuffer` per plane, then `invalidate()` |
| CpuUnpack | original HostPlanes/(Host or HostVisible) → unpacked HostPlanes/Host | Lossless | `unpackToPlanes` on cpu |

The store is generic over an internal `detail::Converter` interface (`from`, `to`, `cost`, `run`), so
the host-only tests use fake converters and fake frames (§12 "frame store … no Vulkan needed").
A `StagingFrame` in `HostReadback` memory offers HostPlanes/HostVisible and VkBuffer/HostVisible
natively, so both are one entry (bytes counted once); one in `HostUpload` memory offers only
VkBuffer/HostVisible. Hence a host view in the staging domain is reachable only through Readback
(the `--via gpu` path, §4.6).

### 5.4 GPU unpack (shader contract)

**Buffer size rule:** a buffer read by the unpack must hold `≥ offset + alignUp(bytes, 4) + 4` bytes
(the shader reads two aligned dwords around any word); the store's original buffers are allocated
with this padding, and `recordUnpack` checks it (`Internal`); a test adopts an unpadded buffer.
Push constants (`UnpackPush` in `src/gpu_unpack.h` and `unpack.slang`; padding explicit so
`sizeof(UnpackPush)` is a stated multiple of 8 — 64 bytes — checked by `static_assert` and compared
with the reflection size at pipeline creation):

```
uint64 base;        // buffer device address + VkBufferB::offset; must be 4-aligned (recordUnpack
                    // checks it: Internal)
uint64 planeOffset; // byte offset of the plane inside the frame
uint stride;        // bytes per row
uint groupBytes, wordBytes, bigEndian, bits;
uint width, height; // the component's grid size
uint samplesPerGroup;
uint slots[3];      // 6 slots of the component: (word << 8 | shift) as 16-bit pairs
uint pad;           // explicit padding to 64 bytes
```
Each invocation (8×8 groups) with `(x, y) < (width, height)`: `g = x / samplesPerGroup`, `k = x %
samplesPerGroup`; the **absolute** byte `abs = planeOffset + y·stride + g·groupBytes +
word(k)·wordBytes`; load the two dwords at `base + (abs & ~3)` and `+4`, shift the 64-bit pair right
by `(abs & 3)·8`, then extract `wordBytes` bytes (correct for any plane offset and alignment, also
custom formats), swap if big-endian, `value = (w >> shift(k)) &
((1 << bits) - 1)`; `imageStore(out, (x, y), value)`. One dispatch per component in one submission;
the recorder overload (§4.2) moves each image to `GENERAL`. The CPU side derives the push constants
from the descriptor (the slots of component c, in index order; at most 6 per component in the
catalogue — `validate()` enforces ≤ 6 for GPU use).

### 5.5 `SourceFactory::open`

1. Scheme → providers whose `schemes()` contain it (a bare path is `file:`); for `file:` read the
   first 4096 bytes on the I/O pool (`FileReader` buffered; a missing file is `Io` at once).
2. `?impl=<id>` → only that provider (unknown id: `Unsupported` listing the ids); else every
   provider's `match()`. Confidences: Y4M magic `YUV4MPEG2 ` 100; explicit `fmt`+size in the query or
   a hint 95; filename with size and format 70; size only 30 (guess `yuv420p`); synthetic 100.
3. Decide: the best has ≥ 60 and no other within 10 → `open(ticket, …)`; best < 60 or a near tie →
   `Ambiguous` (best first); no confidence > 0 → `Unsupported` naming every provider and its `why`.

### 5.6 Raw file read

`RawFileSource::produce(i)`: `offset = i · frameBytes`; aligned range `[alignDown(offset, a),
alignUp(offset + frameBytes, a))`; `allocateHost(desc, rangeBytes, a, offset - alignedOffset)`;
`co_await resumeOn(ctx.io())`; `readAt`; a short read inside the frame is `Io` "truncated frame N of
<file>"; `publish`. `frameCount = size / frameBytes`; a remainder adds the warning "<r> trailing bytes
ignored". Y4M uses the same path with its header offset; its aligned range starts at
`alignDown(offset − 6, a)` so the `FRAME\n` marker before the frame is read too (D15).

### 5.7 CLI shutdown order (leak check)

`dump`/`bench`: detach sources → drop leases → destroy `SourceFactory` and the store (frames retire)
→ `context->drain()` → release context, registries, pools → `finishWithLeakCheck(code)` (dvv-base).

## 7. Error handling

| Situation | Where | `Errc` / behaviour |
|---|---|---|
| File missing, denied, directory | `FileReader::open`, `SourceFactory::open` | `Io` |
| Unbuffered open refused, or the probe read at open refused (`EINVAL`, `ERROR_INVALID_PARAMETER`, …) | `FileReader::open` | not an error: buffered, `unbuffered() == false`, debug log |
| Misaligned `readAt` | `FileReader` | `Internal` |
| Read error; short read inside a frame | `FileReader`, raw/Y4M `produce` | `Io` (file, frame, offset in the message) |
| File size not a multiple of the frame size | raw `open` | warning in `SourceInfo::warnings`; CLI prints it |
| Unknown `fmt`, bad `size`/`fps`/number, Y4M header syntax | providers | `Format` |
| Y4M colourspace outside the catalogue; FRAME parameters; `?impl=` unknown; no provider | providers / factory | `Unsupported` |
| Low confidence or near tie | factory | `Ambiguous` (not an error; CLI exit 3) |
| Frame index outside `[0, frameCount)`; detached origin; adopt of an existing original | sources / store | `Internal` (CLI checks the index first: exit 1) |
| No converter path (target unreachable from Produce in the static graph, or `want.colour` ≠ the frame's colour); GPU view requested from a host-only store | store | `Unsupported` (cached permanently by `(original format, colour-equal, target state)`) |
| Allocation failure (host `bad_alloc`, Vulkan OOM) | store, converters | evict + retry once, then `OutOfMemory` |
| Descriptor invalid | `validate()` | `Format` (catalogue entries are validated by a unit test) |
| Width not a multiple of `widthMultiple` (v210 odd width) | `geometry()` | `Format` "v210 needs a width that is a multiple of 2" |
| Invalid custom-format JSON; a name equal to a catalogue name | `formatFromJson` | `Format` |
| Component whose `info().kind` differs from `InterfaceKind<I>` | `ComponentRegistry::create(caps)` | component unavailable ("kind X does not match interface kind Y") |
| Recorder misuse (image without STORAGE, wrong image count, other device) | dvv-gpu | `Internal` (M1a rule) |
| Unpack `base` not 4-aligned or buffer below the size rule (§5.4) | `recordUnpack` | `Internal` |
| Format without STORAGE_IMAGE support for an unpacked plane | `createImage` | `Unsupported` |
| R8_UINT/R16_UINT without `STORAGE_WRITE_WITHOUT_FORMAT` | Task 0 check, unpack pipeline setup | `Unsupported` (R1 fallback) |
| `DeviceLost` | any GPU step | passed through; recovery in M3 |
| Exceptions in a provider's `match`/`open` or a source's `produce` | factory / store | caught at the boundary → `Internal`, provider disabled for the factory's lifetime (§11) |

## 11. Risks and fallbacks

| # | Risk | Fallback |
|---|---|---|
| R1 | A device (or lavapipe) lacks `shaderStorageImageWriteWithoutFormat`/`…ExtendedFormats`, or STORAGE_IMAGE or `STORAGE_WRITE_WITHOUT_FORMAT` on R8_UINT/R16_UINT. | Unpacked planes become `R32_UINT` (mandatory storage format) with a typed `r32ui` declaration; memory ×2–4 for analysis inputs, decided in Task 0. |
| R2 | Push descriptors unexpectedly unavailable, or the arbiter keeps the spec's bindless heap. | The bindless design of D6's alternative (one extra L task between 5 and 6); the unpack shader changes only its image declaration and index source. |
| R3 | Slang emits a typed image format (`r32ui`) for `RWTexture2D<uint>`, so writes to R16 views are invalid. | `[format("r16ui")]`/`[format("r8ui")]` variants (two pipelines) or the `-default-image-format-unknown` compiler option through a new `dvv_add_shaders(... SLANGC_OPTIONS ...)` argument (Task 5 decides). |
| R4 | `O_DIRECT`/`NO_BUFFERING` refused or slow on some file systems (WSL drvfs, network shares). | Built-in buffered fallback; tests cover both (fallback through the test seam); `bench` reports which mode ran. |
| R5 | Sector size above 4096 or misreported; the flag accepted but the I/O refused. | `alignment()` uses the larger of 4096 and the reported value; the probe at open reads the first `alignment()` bytes and reopens buffered on `EINVAL`/`ERROR_INVALID_PARAMETER` (debug log); `readAt` never reopens, a misaligned call stays `Internal`. |
| R6 | One host memcpy plus one GPU round trip per conversion is too slow for 4K 10-bit 60 fps. | `bench` measures each stage. Fallbacks in order: upload + unpack in one submission (one round trip), several frames in flight via M3 prefetch, reads straight into staging (F3), overlapped I/O (F1). |
| R7 | The single store mutex or the single-flight hand-off races or deadlocks under TSan. | Lock rules of §5.2 (nothing called under the lock), a 20× TSan loop in Tasks 7a and 7b; shards only if contention is measured. |
| R8 | A layout golden is derived wrongly (the same mistake in table and golden). | Goldens are written from FFmpeg's `pixdesc.c`/`v210dec.c` text by one agent and checked by both reviewers against those sources; M4 adds the `extractplanes`/`framemd5` oracle for every format. A local one-off check with an `ffmpeg` CLI, when the developer has one, is allowed and not committed. |
| R9 | Reading two dwords past a plane's end at the buffer's last bytes, or a misaligned base. | Buffer size rule `≥ offset + alignUp(bytes, 4) + 4` and a 4-aligned `base`, both checked by `recordUnpack` (`Internal`) (§5.4); the shader loads at the absolute byte address, so plane offsets need no alignment; a GPU test uses sizes whose frame size is not a multiple of 4, and one adopts an unpadded buffer. |
| R10 | Y4M files with per-frame parameters or a different header line ending. | `Unsupported` with a clear message; an index scan over the file (sequential access) is Future F6. |
| R11 | Coroutine lifetime: a joiner destroyed while suspended, or a produce task outliving a detached source. | No cancellation in M2 (D10); the store keeps the source alive during `produce` (the plan step holds a `shared_ptr<ISource>`); waiters are never destroyed by the store. |
| R12 | `ComponentRegistry` creation from a static initialiser or a missing `dvv_link_components` drops the providers silently. | `SourceFactory::create` fails with `Unsupported` "no source providers registered" when the list is empty; the CLI e2e test opens all three schemes. |

## 12. Future (not built in M2)

- **F1:** Windows IOCP reads (the overlapped handle with a blocking wait is in M2); Linux `io_uring`
  (if the `bench` rule of D18 names the produce stage: M3 item).
- **F2:** `MappedFrame` (read-only mmap) as a zero-copy host original.
- **F3:** Reads straight into staging (`StagingFrame` from the reader) where the memory allows DMA.
- **F4:** Upload and unpack in one submission; pipelined conversions with real `SyncPoint`s and
  `lease.retire(lastUse)`; a transfer queue if the D18 rule triggers.
- **F5:** Specialisation-constant fast paths for common formats; `copyBufferToImage` for formats whose
  planes already equal the unpacked layout.
- **F6:** Y4M per-frame parameters (index scan); Y4M interlace/aspect handling; sidecar format files
  (`IFormatDetector`).
- **F7:** More catalogue entries (abgr, rgb0/bgr0, yvyu422, nv16, p210le, yuva*, gbrap, bayer, float).
- **F8:** `AVPixelFormat` mapping and zero-copy `AVFrame` wrapping (M4 with FFmpeg); FFmpeg
  `extractplanes`/`framemd5` oracle for every format (M4).
- **F9:** Sharded store index, `VK_EXT_memory_budget` budgets, adaptive prefetch with cancellation, the
  frame-store debug panel (M3).
- **F10:** Image pooling in `ResourcePool` (needs the lease design noted in M1a); when measured.
- **F11:** `ToDisplay` with the colour engine (M3), `Downscale`, `HostImageCopy` when supported.
- **F12:** A bindless heap if push-descriptor limits ever bind (user shaders with many inputs, v1.x).
